# Прозрачная вакансия

Прототип помогает редактору вакансий Калининградской области подготовить уточнения для работодателя. Отчёт проверяет название должности, обязанности, требования, оплату, график, место работы и тип занятости. У замечаний есть исходные данные и конкретные вопросы по условиям.

[Демонстрация](demo.mp4?raw=true) · [Проверка на реальных карточках](evaluation/portal-review.md)

## Быстрый запуск в Docker

1. На GitHub выберите **Code → Download ZIP** и распакуйте архив. Откройте терминал в папке, где лежит `compose.yaml`. Если репозиторий уже клонирован, откройте его папку.
2. На Windows установите и запустите Docker Desktop с WSL 2 в режиме Linux-контейнеров. На Linux установите Docker Engine и плагин Compose v2. Проверьте наличие Compose командой `docker compose version`. [Установка на Windows](https://docs.docker.com/desktop/setup/install/windows-install/) · [Установка Compose](https://docs.docker.com/compose/install/)
3. Выберите режим. Эти команды одинаковы для PowerShell и Linux.

| Что запустить | Команда | Файл отчёта в папке проекта |
| --- | --- | --- |
| Проверить четыре учебные вакансии | `docker compose run --build --rm report` | `reports/sample-report.json` |
| Загрузить вакансии Калининградской области через API «Работа в России» | `docker compose run --build --rm live` | `reports/report.json` |

При первой сборке Docker может скачать базовый образ. Учебные данные уже лежат в репозитории. После запуска терминал покажет количество проверенных вакансий и путь к отчёту. Откройте файл в любом текстовом редакторе. Например, учебный отчёт можно открыть командой `notepad .\reports\sample-report.json` в PowerShell или `less reports/sample-report.json` в Linux. В каждом объекте JSON поле `issues` содержит замечания и вопросы для работодателя.

Если API недоступен, команда `live` напечатает ошибку. Последний успешный `reports/report.json` сохранится, если он уже есть. Учебный режим можно запустить отдельно.

### Как проверить запросы к API

Для короткой проверки рабочего режима создайте файл `.env` рядом с `compose.yaml` и задайте лимит.

```dotenv
VACANCY_LIMIT=4
```

Запустите `docker compose run --build --rm live`. При достаточном числе вакансий в журнале появятся запросы с `offset=0` и `offset=1`. Откройте `reports/report.json` после сообщения о сохранении отчёта.

В `.env` можно указать URL через `VACANCY_SOURCE` и тайм-аут в секундах через `VACANCY_TIMEOUT`. Для HTTP-адреса из задания добавьте две строки.

```dotenv
VACANCY_SOURCE=http://opendata.trudvsem.ru/api/v1/vacancies/region/39
VACANCY_ALLOW_HTTP=1
```

Если контейнер не может записать файл в Linux, добавьте `--user "$(id -u):$(id -g)"` перед именем сервиса (`report` или `live`).

## Проверочный запуск с Python

Если Docker не установлен, достаточно Python 3.10 или новее. Используется только стандартная библиотека. Локальная модель работает без интернета, регистрации и ключей.

В Windows откройте PowerShell в папке проекта.

```powershell
py analyze_vacancies.py examples/vacancies.json --output reports/sample-report.json
py -m unittest -v
```

Если установленный Python запускается командой `python`, используйте её вместо `py`.

В Linux выполните следующие команды из папки проекта.

```sh
python3 analyze_vacancies.py examples/vacancies.json --output reports/sample-report.json
python3 -m unittest -v
```

### Свой JSON или данные организаторов

Положите файл `vacancies.json` в папку проекта или укажите путь к файлу в кавычках. Результат будет в `reports/file-report.json`. На Windows используйте `py` вместо `python3`.

```sh
python3 analyze_vacancies.py "vacancies.json" --output reports/file-report.json
```

Принимается один ответ API v1 с `results.vacancies` либо массив таких страниц. Анализируются все уникальные вакансии. Пробелы по краям ID удаляются. При конфликтующих дублях используется более свежая запись, если обе карточки содержат сравнимое время обновления с часовым поясом. В остальных случаях берётся последняя запись по порядку входа. Решение отмечается в журнале. [Учебный JSON](examples/vacancies.json) содержит вымышленные вакансии. GitHub Actions сверяет отчёт из Docker с [эталоном](examples/report.json).

## Сценарий редактора «до и после»

Учебная карточка сообщает о графике `2/2` в структурированном поле и `5/2` в описании. Первый отчёт показывает обе цитаты и вопрос к работодателю. Во второй версии учебной карточки описание приведено к графику `2/2`.

```sh
python3 analyze_vacancies.py examples/vacancies.json --output reports/before.json
python3 analyze_vacancies.py examples/vacancies-corrected.json --output reports/after.json
python3 compare_reports.py reports/before.json reports/after.json --output reports/comparison.json
```

На Windows вместо `python3` используйте `py`. В учебном примере снято одно замечание о графике, 17 остались. В `reports/comparison.json` сводка находится в `summary`, подробности по ID — в `vacancies`. Замечания сопоставляются по теме, формулировке проблемы и набору полей. Если есть единственная пара с новой цитатой, рекомендацией или методом, она появляется в `changed`. Новые и исключённые карточки перечисляются отдельно от исправлений. Команды работают на локальных JSON без сети.

## Рабочий запуск

Точка входа — `run_report.py`. Скрипт запрашивает страницы API региона 39 и передаёт карточки тому же анализатору, который работает с локальным JSON. По умолчанию лимит в 20 уникальных вакансий и размер страницы 10 дают как минимум две страницы, когда данных достаточно. [Документация API «Работа в России»](https://trudvsem.ru/opendata/api)

```sh
python3 run_report.py --limit 20 --output reports/report.json
```

В PowerShell замените `python3` на `py`.

| Аргумент | Назначение |
| --- | --- |
| `--url` | URL источника или переменная `VACANCY_SOURCE`. По умолчанию API портала «Работа в России» для региона 39. |
| `--limit` | Максимальное число уникальных вакансий или переменная `VACANCY_LIMIT`. По умолчанию 20. |
| `--timeout` | Тайм-аут одного HTTP-запроса в секундах или переменная `VACANCY_TIMEOUT`. По умолчанию 60. |
| `--output` | Путь к выходному JSON. |

Журнал сообщает `offset`, размер запроса и число полученных записей. При временном сбое выполняется одна повторная попытка. Ошибки TLS, перенаправления и невалидный JSON прерывают запуск. Новый отчёт проходит проверку, записывается во временный файл в каталоге назначения и атомарно заменяет предыдущий. Сбой до замены сохраняет предыдущий файл. При ошибке синхронизации каталога после замены выводится предупреждение. Блокировка действует от чтения входа до публикации отчёта. Соседний файл `*.json.lock` служит для синхронизации процессов и должен оставаться на месте.

Проверка живого API 24 ноября 2026 года при `limit=2` и `offset=0,1,2` дала по две записи на страницу и шесть уникальных ID. Значение `meta.total` было одинаковым (4232). Поэтому запросы используют `offset` как номер страницы. Уменьшение `meta.total`, повтор страницы и преждевременная пустая страница завершают обновление ошибкой.

### Настройки источника и лимиты

По умолчанию разрешён HTTPS на `opendata.trudvsem.ru:443`. Соединение идёт напрямую по проверенному DNS-адресу. TLS проверяет имя хоста. Системные HTTP-прокси игнорируются. Правила исходящего трафика на сервере должны ограничивать доступ утверждёнными источниками. [Контроль исходящих запросов](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)

| Переменная | Назначение |
| --- | --- |
| `VACANCY_ALLOWED_ORIGINS` | Дополнительные разрешённые источники в виде `https://имя:порт` через запятую. URL для запроса по-прежнему задаётся через `VACANCY_SOURCE`. |
| `VACANCY_ALLOW_HTTP` | Значение `1` разрешает явный HTTP-запуск на разрешённом источнике. |
| `VACANCY_PRIVATE_ORIGINS` | Явно доверенные внутренние источники для администратора или тестов. |
| `VACANCY_DEADLINE`, `VACANCY_MAX_PAGES` | Сетевой бюджет в секундах и предел страниц. По умолчанию 300 секунд и 100 страниц. |
| `VACANCY_LOCAL_BYTES`, `VACANCY_JSON_DEPTH`, `VACANCY_FIELD_CHARS`, `VACANCY_FRAGMENTS` | Пределы при запуске через Python. По умолчанию 64 МиБ на локальный файл, глубина 32, длина поля 32 768 символов и 64 фрагмента на тему. |

Для API действует предел 8 МиБ на страницу и 64 МиБ на всю загрузку. При превышении лимита обработка завершается ошибкой. JSON с повторяющимися ключами, бесконечными числами и пустыми или несовместимыми ID отклоняется. В результате остаются замечания по всем обработанным условиям в пределах принятого входа.

## Автоматический запуск

В GitHub Actions отчёт запускается ежедневно в 05:17 UTC (07:17 по Калининграду). Расписание меняется в `cron`. Для ручного запуска откройте **Actions → Vacancy report → Run workflow**. Переменные репозитория `VACANCY_SOURCE`, `VACANCY_LIMIT` и `VACANCY_TIMEOUT` управляют источником, лимитом и тайм-аутом. Ручной и запланированный запуски вызывают одну команду. [Конфигурация workflow](.github/workflows/report.yml)

Рабочие отчёты остаются внутри запуска GitHub Actions по умолчанию. Для согласованной публикации установите переменную репозитория `VACANCY_PUBLISH_REPORT=true`. После успешного запуска архив `vacancy-report` доступен в **Artifacts**. Для постоянного хранения предыдущего отчёта используйте systemd и локальный каталог. Тестовый workflow публикует отчёт на вымышленных данных и проверяет сборку Docker, историю Git, Python-код, синтаксис workflow и высокие/критические уязвимости образа. Результаты Trivy выводятся в журнале. [Скачивание артефактов](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/download-workflow-artifacts)

Если облачный runner возвращает сетевые ошибки, этот же скрипт можно запускать по расписанию на Linux-хосте, которому доступен портал. Пользовательский таймер systemd настроен на 07:17 по Калининграду. Выполните команды из корня проекта. Ссылку `~/.local/share/transparent-vacancy` достаточно создать один раз.

```sh
mkdir -p ~/.local/share
ln -sT "$(pwd -P)" ~/.local/share/transparent-vacancy
install -Dm644 systemd/transparent-vacancy.service ~/.config/systemd/user/transparent-vacancy.service
install -Dm644 systemd/transparent-vacancy.timer ~/.config/systemd/user/transparent-vacancy.timer
systemctl --user daemon-reload
systemctl --user enable --now transparent-vacancy.timer
systemctl --user start transparent-vacancy.service
```

Отчёт сохраняется в `${XDG_STATE_HOME:-$HOME/.local/state}/transparent-vacancy/latest.json`. Настройки URL, лимита и тайм-аута можно задать в `~/.config/transparent-vacancy/config.env` строками `ИМЯ=значение`. Расписание меняется через `systemctl --user edit transparent-vacancy.timer`. В секции `[Timer]` задайте пустой `OnCalendar=` и затем нужное расписание вторым `OnCalendar=...`. После изменения перезапустите таймер. Журнал доступен через `journalctl --user -u transparent-vacancy.service -n 30`.

Для системной установки администратор размещает репозиторий по пути `/opt/transparent-vacancy`, устанавливает [системную службу](systemd/system/transparent-vacancy.service) и существующий таймер в `/etc/systemd/system`, затем загружает unit-файлы через `systemctl daemon-reload` и включает таймер через `systemctl enable --now transparent-vacancy.timer`. Служба использует динамического непривилегированного пользователя, настройки из `/etc/transparent-vacancy/config.env` и пишет в `/var/lib/transparent-vacancy/latest.json`.

## Анализ карточки

Анализатор учитывает текст и структурированные поля. Например, конкретный график в описании закрывает вопрос к полю «Гибкий график». Если два источника дают несовместимые условия, например `2/2` и `5/2`, отчёт приводит обе цитаты. Рекомендации подсказывают, какие факты следует уточнить у работодателя.

Локальный классификатор в `clarity_model.py` ищет расплывчатые фразы по семи темам. Он строит символьные триграммы, сравнивает их с размеченными фразами по косинусному сходству и применяет порог уверенности. Если модель отмечает неоднозначность и конкретных сведений по теме в карточке нет, формируется замечание с методом `nearest_neighbor`. Проверяемые факты и противоречия обрабатывают правила. Рекомендации составлены заранее и привязаны к теме проверки.

В четвёртой учебной карточке модель добавляет замечание к новой формулировке «Решение текущих задач руководства отдела». Тест `test_model_adds_issue_on_paraphrase` показывает, что без ответа модели замечание об обязанностях в этом случае исчезает. Словарь и обучающие фразы ограничивают покрытие редких формулировок. [Классификатор](clarity_model.py) · [Тест](test_report.py)

### Экспериментальный классификатор

Для разработки доступны [разметка 1-NN](datasets/baseline.jsonl), обучение TF-IDF + Logistic Regression и сравнение на независимой выборке. Подготовьте `datasets/train.jsonl`, `datasets/validation.jsonl` и `datasets/test.jsonl` с полями `text`, `topic`, `label` (1 для неоднозначности), `vacancy_id`, `source` и `group` для близких фраз. Разведите вакансии и группы между выборками. Разметка baseline предназначена для 1-NN. Учебные данные организаторов исключаются из обучения и подбора порогов.

```sh
python3.12 -m venv .venv-train
.venv-train/bin/python -m pip install -r requirements-train.txt
.venv-train/bin/python training/train.py
.venv-train/bin/python evaluation/evaluate.py
```

Обучение проверяет совпадение прогнозов scikit-learn и реализации на стандартном Python. Экспорт содержит словари, IDF, коэффициенты и пороги с SHA-256. Для темы без порога с Precision ≥ 0,8 на валидации экспериментальная модель воздерживается от замечаний. Оценка сравнивает правила, правила с 1-NN и правила с линейным классификатором по Precision, Recall, Macro-F1, числу ложных замечаний, времени и пику выделений памяти Python. Доступного независимого размеченного набора пока нет. В отчётах используется 1-NN.

## Формат JSON

Отчёт — массив объектов, по одному на уникальный ID. Поле `url` появляется, если карточка содержит `vac_url`. Поле `issues` всегда присутствует и содержит пустой массив, если замечаний нет.

| Поле замечания | Содержание |
| --- | --- |
| `topic` | Тема из `job_title`, `duties`, `requirements`, `salary`, `schedule`, `location`, `employment`. |
| `source_fields` | Пути к полям карточки API, включая индексы массивов. При пропуске перечисляются проверенные поля. |
| `source_value` | Цитата или исходное значение целиком, если точный фрагмент после разбора HTML восстановить нельзя. Для пропуска — пустая строка. Для противоречия — объект с обоими источниками и значениями. Если две цитаты из одного поля, передаётся массив объектов `{field, value}`. |
| `problem` | Что пропущено, неясно или противоречит другой части карточки. |
| `recommendation` | Конкретный вопрос или уточнение для работодателя. |
| `method` | `rule` или `nearest_neighbor`. |

Обрабатываются вакансии, которые передаёт API региона 39, в пределах выбранного лимита.
