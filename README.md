# Прозрачная вакансия

Прототип помогает редактору вакансий Калининградской области подготовить уточнения для работодателя. Отчёт проверяет название должности, обязанности, требования, оплату, график, место работы и тип занятости. У замечаний есть исходные данные и конкретные вопросы по условиям.

## Проверочный запуск для жюри

Нужен Python 3.10 или новее. Используется только стандартная библиотека. Модель запускается локально, без интернета, регистрации и ключей. Выполните команды из корня репозитория.

```sh
python analyze_vacancies.py examples/vacancies.json --output report.json
python -m unittest -v
```

В Linux вместо `python` можно использовать `python3`. Для проверочных данных организаторов замените `examples/vacancies.json` на свой файл. Принимается один ответ API v1 с `results.vacancies` либо массив таких страниц. Анализируются все вакансии из файла. Для повторяющегося ID берётся последняя карточка. [Пример данных](examples/vacancies.json) и [пример отчёта](examples/report.json) используют вымышленные карточки в формате API.

## Рабочий запуск

Точка входа — `run_report.py`. Скрипт запрашивает страницы API региона 39 и передаёт карточки тому же анализатору, который работает с локальным JSON. По умолчанию лимит в 20 уникальных вакансий и размер страницы 10 дают как минимум две страницы, когда данных достаточно. [Документация API «Работа в России»](https://trudvsem.ru/opendata/api)

```sh
python run_report.py --limit 20 --output report.json
```

| Аргумент | Назначение |
| --- | --- |
| `--url` | URL источника или переменная `VACANCY_SOURCE`. По умолчанию API портала «Работа в России» для региона 39. |
| `--limit` | Максимальное число уникальных вакансий или переменная `VACANCY_LIMIT`. По умолчанию 20. |
| `--timeout` | Тайм-аут одного HTTP-запроса в секундах или переменная `VACANCY_TIMEOUT`. По умолчанию 60. |
| `--output` | Путь к выходному JSON. |

Журнал сообщает `offset`, размер запроса и число полученных записей. При временном сетевом сбое выполняется повторный запрос. Загрузчик проверяет общий бюджет в 300 секунд между сетевыми операциями и ограничивает размер страницы 8 МиБ. Новый отчёт атомарно заменяет предыдущий только после успешной загрузки и анализа. Если очередную страницу получить не удалось, команда возвращает код 1 и прежний файл остаётся доступным.

При сетевой ошибке на стандартном HTTPS-адресе следующая попытка начинается с первой страницы официального HTTP-адреса региона 39. Проверка структуры ответа и сохранение отчёта одинаковы для обоих адресов. Пользовательский URL и ошибки проверки сертификата обрабатываются на исходном протоколе.

## Автоматический запуск

В GitHub Actions отчёт запускается ежедневно в 05:17 UTC (07:17 по Калининграду). Расписание меняется в `cron`. Для ручного запуска откройте **Actions → Vacancy report → Run workflow**. Переменные репозитория `VACANCY_SOURCE`, `VACANCY_LIMIT` и `VACANCY_TIMEOUT` управляют источником, лимитом и тайм-аутом. Ручной и запланированный запуски вызывают одну команду. [Конфигурация workflow](.github/workflows/report.yml)

Успешный запуск сохраняет файл в артефакте `vacancy-report`. Если обновление завершается ошибкой, артефакт последнего успешного запуска остаётся доступен на его странице в пределах настроенного срока хранения. Просмотр работы расписания и загрузки страниц доступен в журнале workflow.

Если облачный runner возвращает сетевые ошибки, этот же скрипт можно запускать по расписанию на Linux-хосте, которому доступен портал. Пользовательский таймер systemd настроен на 07:17 по Калининграду. Выполните команды из корня проекта. Ссылку `~/.local/share/transparent-vacancy` достаточно создать один раз.

```sh
mkdir -p ~/.local/share
ln -sT "$(pwd -P)" ~/.local/share/transparent-vacancy
install -Dm644 systemd/transparent-vacancy.service ~/.config/systemd/user/transparent-vacancy.service
install -Dm644 systemd/transparent-vacancy.timer ~/.config/systemd/user/transparent-vacancy.timer
systemctl --user daemon-reload
systemctl --user enable --now transparent-vacancy.timer
systemctl --user start transparent-vacancy.service
```

Отчёт сохраняется в `${XDG_STATE_HOME:-$HOME/.local/state}/transparent-vacancy/latest.json`. Настройки URL, лимита и тайм-аута можно задать в `~/.config/transparent-vacancy/config.env` строками `ИМЯ=значение`. Расписание меняется через `systemctl --user edit transparent-vacancy.timer`. В секции `[Timer]` задайте пустой `OnCalendar=` и затем нужное расписание вторым `OnCalendar=...`. После изменения перезапустите таймер. Журнал доступен через `journalctl --user -u transparent-vacancy.service -n 30`.

## Анализ карточки

Анализатор учитывает текст и структурированные поля. Например, конкретный график в описании закрывает вопрос к полю «Гибкий график». Если два источника дают несовместимые условия, например `2/2` и `5/2`, отчёт приводит обе цитаты. Рекомендации подсказывают, какие факты следует уточнить у работодателя.

Локальный классификатор в `clarity_model.py` ищет расплывчатые фразы по семи темам. Он строит символьные триграммы, сравнивает их с размеченными фразами по косинусному сходству и применяет порог уверенности. Если модель отмечает неоднозначность и конкретных сведений по теме в карточке нет, формируется замечание с методом `nearest_neighbor`. Проверяемые факты и противоречия обрабатывают правила. Рекомендации составлены заранее и привязаны к теме проверки.

В четвёртой учебной карточке модель добавляет замечание к новой формулировке «Решение текущих задач руководства отдела». Тест `test_model_adds_issue_on_paraphrase` показывает, что без ответа модели замечание об обязанностях в этом случае исчезает. Словарь и обучающие фразы ограничивают покрытие редких формулировок. [Классификатор](clarity_model.py) · [Тест](test_report.py)

## Формат JSON

Отчёт — массив объектов, по одному на уникальный ID. Поле `url` появляется, если карточка содержит `vac_url`. Поле `issues` всегда присутствует и содержит пустой массив, если замечаний нет.

| Поле замечания | Содержание |
| --- | --- |
| `topic` | Тема из `job_title`, `duties`, `requirements`, `salary`, `schedule`, `location`, `employment`. |
| `source_fields` | Пути к полям карточки API, включая индексы массивов. При пропуске перечисляются проверенные поля. |
| `source_value` | Исходное значение или цитата из текста без HTML-разметки. Для пропущенного поля — пустая строка. Для противоречия — объект с обоими источниками и значениями. Если две цитаты из одного поля, передаётся массив объектов `{field, value}`. |
| `problem` | Что пропущено, неясно или противоречит другой части карточки. |
| `recommendation` | Конкретный вопрос или уточнение для работодателя. |
| `method` | `rule` или `nearest_neighbor`. |

Обрабатываются вакансии, которые передаёт API региона 39, в пределах выбранного лимита.

Ролик длится 1 минуту 15 секунд. В нём показаны загрузка двух страниц с учебного HTTP-сервера в формате API, работа модели, обе цитаты для конфликтующего графика и сохранение отчёта после сбоя второй страницы. [Скачать демонстрацию](demo.mp4?raw=true)
