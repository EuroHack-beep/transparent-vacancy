

Прототип для редактора вакансий Калининградской области. Для каждой карточки сервис проверяет название должности, обязанности, требования, оплату, график, место работы и тип занятости. Для замечаний сохраняет исходные значения и формирует вопросы работодателю.

## Запуск

Понадобится Python 3.10 или новее. Обе команды выполняются из корня проекта. Все зависимости входят в стандартную библиотеку Python.

Проверка локального ответа API, включая анализ моделью, работает без сети и регистрации. Замените путь к примеру на путь к JSON организаторов. Файлы в каталоге `examples` содержат вымышленные данные и образец отчёта.

```shell
python analyze_vacancies.py examples/vacancies.json --output report.json
```

Рабочий режим начинается в `run_report.py`. Сервис запрашивает страницы API, объединяет вакансии по ID и передаёт их тому же анализатору. Параметр `--limit` ограничивает число уникальных вакансий, `--url` задаёт адрес источника. После успешной обработки новый файл атомарно заменяет предыдущий. При сбое процесс завершается с кодом 1 и сохраняет последний успешный отчёт.

```shell
python run_report.py --limit 20 --output report.json
python -m unittest -v
```

## Автоматический запуск

Конфигурация GitHub Actions находится в `.github/workflows/report.yml`. После размещения в основной ветке репозитория с включёнными Actions запуск запланирован ежедневно на 05:17 UTC (08:17 по Москве). Время меняется в поле `cron`. Ручной запуск доступен в **Actions → Vacancy report → Run workflow**. В настройках Actions можно задать переменные репозитория `VACANCY_SOURCE` и `VACANCY_LIMIT`. Отчёт доступен в артефакте `vacancy-report` успешного запуска в пределах срока хранения артефактов репозитория.

## Как работает анализ

Правила сопоставляют описание с полями API. Например, сведения об опыте в `requirement.experience` учитываются и при пустом текстовом поле требований. Если положительный минимум зарплаты превышает максимум, отчёт приводит оба исходных значения.

Локальная модель в `clarity_model.py` классифицирует фразы методом одного ближайшего соседа. Обучающие примеры подписаны тремя классами: неопределённый график, неопределённая оплата и прочие фразы. Модель сравнивает наборы трёхсимвольных фрагментов слов по косинусному сходству. Порог сходства и отрыв от второго класса позволяют пропускать неуверенные ответы. Если модель распознала неоднозначность и правила не нашли конкретизирующих сведений в других полях, в отчёт попадает уточнение. Рекомендации подготовлены заранее для каждой темы. Небольшой набор примеров и словарь правил ограничивают распознавание необычных выражений.

В демонстрационном файле у обеих вакансий записано «Гибкий график работы». У второй вакансии есть дни и часы в `conditions`. Поэтому вопрос о графике появляется только у первой. Это можно проверить в `examples/report.json`.

## Формат отчёта

Отчёт — массив объектов, по одному на ID. Поле `id` содержит идентификатор вакансии, `url` — ссылку при наличии, `issues` — список замечаний. Пустой список означает, что выполненные проверки ничего не выявили. При дублировании ID локальный анализатор использует последнюю запись.

У каждого замечания есть тема `topic`, пути исходных полей `source_fields`, цитата или исходное значение `source_value`, пояснение `problem` и вопрос либо действие `recommendation`. Пропуск обозначается пустой строкой, противоречие содержит оба значения. Поле `method` указывает способ обнаружения: `rule` для правила и `nearest_neighbor` для классификатора.
